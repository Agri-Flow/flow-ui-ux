Slide-Over Form

Right-anchored 480 px sheet for multi-field forms. Use when the user is creating or editing a record with 3+ fields and the surrounding context (table, profile, list) should remain visible. Confirmations and single-decision dialogs use the centered modal pattern instead — never mix the two.

In production: see e2-supplier-registration.html. Same pattern is used for Add User and Add Product Mapping.

Usage

Use for

  • Creating a record with 3+ fields (Add User, Register Supplier, Add Product Mapping).
  • Editing a record where the surrounding context (table, profile) should stay visible.
  • Multi-section forms that benefit from a vertical scroll.

Don't use for

  • Single-decision confirmations (Deactivate User, Suspend Supplier) — use the centered modal instead.
  • Destructive actions or alerts — centered modal with tone-colored icon circle.
  • Editing one field inline — use the table row's "Edit" button or popover.
  • Full-page workflows (multi-step wizards) — promote to a dedicated route.

Behavior

  • ·Open trigger: a primary CTA button on the parent page (e.g. "Register Supplier" on the directory). The button uses the same primary styling — pill or rounded-md is the parent page's decision.
  • ·Close: backdrop click, ESC key, header × button, Cancel button, successful submit.
  • ·Body overflow: form body scrolls independently of the sticky header and footer. Page behind it is locked (document.body.style.overflow = "hidden").
  • ·Validation: inline beneath each field. Required-field asterisk turns into an error message on submit attempt with empty value. Required errors must not appear before the user has interacted.
  • ·Audit trail: every successful submission writes an entry to audit_logs. Where helpful, surface this in the info box ("This action will be recorded in the audit log").
  • ·Mobile: on viewports < 480 px the panel takes 100 vw; otherwise the 480 px width is fixed.
