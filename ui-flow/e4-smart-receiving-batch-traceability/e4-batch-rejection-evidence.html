Spec

Build commentary only. Nothing on this rail is product copy — a warehouse clerk never sees any of it.

re: Screen

The Reject branch of the batch-intake form, drawn on its own canvas — e4-batch-intake-qc.html. Tablet-first: the clerk is standing at the receiving gate holding the device.

re: Batch context

Traceability ID, supplier, product and weight are carried from the intake form and are read-only here. The client must not be able to alter them on the rejection path.

re: Reason code

A fixed six-value enum — temperature abuse, physical damage, pest contamination, wrong SKU, quality below grade, other. Free text alone is never an accepted rejection reason, because an unstructured note cannot be aggregated into supplier scorecards or defended at inspection. Validate the code server-side against the enum; do not accept an arbitrary string.

re: Reason code › Describe the reason

Conditionally required: mandatory when and only when the code is other. Render the field as absent, not disabled, for every other code, and clear its value on change so stale text can never travel with the batch. Enforce the same conditional requirement server-side — a database check constraint over (reason code, note) is the intended backstop, not client validation alone.

re: Photo evidence

One to five photos, hard-capped. The sixth is refused client-side before any upload is attempted and refused again server-side. A rejection row without at least one confirmed photo key is invalid — the same check constraint that guards the conditional note guards evidence presence.

re: Photo evidence › Upload

Photos go to private object storage under a per-rejection key prefix; the bucket is never publicly addressable. Uploads use short-lived pre-signed links (15-minute lifetime) generated on demand, and every subsequent read is itself logged. The object key is deliberately not surfaced in the UI — the clerk sees the file name and size only.

re: Photo evidence › Slot states

Four terminal-ish slot states — uploaded, uploading, pending, failed. Each is rendered with an icon and a word, never colour alone: the warehouse floor is not a colour-accurate viewing environment, and the accessibility baseline forbids colour-only meaning.

re: Before you can submit

The four listed conditions are the server-side validation rules, mirrored in the UI so a disabled button is never unexplained. Client-side gating is a courtesy; the server re-checks all four and rejects the submission independently.

re: Record Rejected Batch

Emits receiving.batch_rejected into the append-only audit_logs table with the reason code, the note and every photo key. Quarantine routing is programmatic — the client must not be able to place a rejected batch into sellable stock.

re: Compliance footer

Retention provenance: audit entries 5 years per Rwanda FDA Law N°003/2018; rejection photos a 2-year minimum. Neither is ever hard-deleted — soft-delete only, in line with the workspace-wide retention rule.
