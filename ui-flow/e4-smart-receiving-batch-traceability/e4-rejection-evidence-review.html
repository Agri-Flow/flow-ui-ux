Spec

Build commentary only. Nothing on this rail is product copy — a Manager or an inspector never sees any of it.

re: Screen

Read-only by construction — there is no edit path to captured evidence, and the server refuses a mutation against it. The two audiences are a Manager weighing a quarantine override and an inspector during an FDA audit; design for both reading the same record.

re: Batch header

Every value here is read from the batch record written at intake — Traceability ID, weight, expiry and inspector are never recomputed on this screen. Expiry shows the value computed at intake, not a fresh derivation.

re: Photo evidence

Photos are private storage objects. They are never publicly addressable and are served only through short-lived pre-signed links generated on demand, one per view, expiring after 1 hour. Nothing is cached indefinitely and no link is persisted with the batch record.

re: Refresh links

Re-issues the pre-signed links for this batch. It never re-fetches or mutates the underlying objects — an expired link is a lapsed grant, not missing evidence.

re: Reason for rejection

Stored as a fixed reason code — one of six — and rendered here in plain language. Free text is never accepted for the code itself.

re: Clerk's note

The note is mandatory when the reason code is Other and optional otherwise; whatever the Clerk entered is retained verbatim. Render it, never summarise or truncate it.

re: Access is logged

Opening this panel emits receiving.rejection_photos_viewed into the append-only audit_logs table with the viewing user and this batch. Viewing evidence is itself a compliance event — the write happens on read, which is unusual and must not be optimised away.

re: Retention

Photo objects: 2 years minimum. audit_logs entries: 5 years (Rwanda FDA). Pre-signed link lifetime: 1 hour. Evidence is soft-deleted only and survives an override — releasing the batch from quarantine never erases why it was rejected.

re: Alternate state · Not permitted

Authorised to view: Warehouse QC Clerk, Warehouse Manager, Admin, Procurement, Operations, Finance. Denied: Driver, Supermarket Manager, Supplier. A denied attempt is itself written to audit_logs — enforce server-side; hiding the route in the client is not the control.

re: Alternate state · No photos on this batch

⚠ Open question — do not resolve while building. This state's copy asserts a batch can reach QUARANTINE by a route other than a QC rejection. Under the current spec that route does not exist: Story 4.1 Scenario 2 makes REJECT → QUARANTINE the only creation path, and Story 4.3's database constraint makes an evidence-less REJECT impossible — so as specified the state is unreachable. Task 4.3.1's own integration test points the same way — a batch with zero photos returns 404, not a 200 with an empty set — so there is no contract under which this panel renders. Logged as [AC-DRIFT] in reports/story-coverage/epic-4-story-coverage.md and awaiting a founder ruling. Build the state as drawn; do not delete it and do not reword the copy on the strength of this note.

re: Photo lightbox

The countdown reflects the remaining life of the pre-signed link for the photo being viewed, not a session timeout. Paging between photos does not re-issue links — all four are granted in the same batch.

re: Compliance footer

Provenance for the rules above: 2-year evidence retention and no-hard-delete follow Rwanda FDA / RICA evidence requirements; the 5-year append-only audit retention follows Rwanda FDA Law N°003/2018.
